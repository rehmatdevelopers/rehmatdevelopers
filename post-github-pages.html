Guide: Deploying Your Static Website on GitHub Pages

Tutorials📅 December 2025⏱ 2 min read👤 Muhammad Waleed

GitHub Pages is a solid free option for static sites (HTML, CSS, JavaScript). It includes HTTPS and is well suited to portfolios, documentation, and simple business marketing sites. It is not a host for server languages like PHP or a custom Node backend.

Step-by-step

  1. Prepare files: Keep a clear folder structure with index.html at the root.
  2. Create a GitHub repository: Public repos work with GitHub Pages on the standard free plan.
  3. Push your code: Commit and push to the branch you will publish (often main).
  4. Enable Pages: Repo → Settings → Pages.
  5. Choose source: Select “Deploy from a branch”, then the branch and folder.
  6. Wait for the build: After a short deploy, open the provided *.github.io URL over HTTPS.

Custom domain

You can attach a domain you own by adding it in Pages settings and creating the DNS records (like CNAME or A records) your registrar requires.

Configure the publishing source

After pushing the site files to the repository, open the repository settings and locate the Pages section. Choose the branch and folder that contain the site, then save the publishing configuration. GitHub Pages will publish the static files at the generated project address once the deployment completes. The first publish can take a little time, so check the Pages status rather than repeatedly changing settings.

Check paths and project URLs

For a project site, the repository name is commonly part of the public URL. Use relative paths such as css/style.css and images/logo.png when the same folder structure is deployed together. Avoid assuming that a root path such as /images/logo.png points to the project repository; on a project site it may point to the domain root instead. Test every navigation link, image, stylesheet, and script on the published address.

Know the platform limits

GitHub Pages serves static content. A form that needs to store submissions, user accounts, or private database records requires a separate backend or trusted form service. Never put passwords, API secrets, or private credentials in front-end JavaScript. Keep the repository organized and review deployment status whenever a change does not appear online.
